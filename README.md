# @uncle7/starmap-2d

**把按标准结构组织的站点内容，变成一张可截图的宇宙航行星图。**
二级是一段可以钻进去的**光隧**。

库不知道你的内容是什么。它只认 `Manifest` 这一个结构。

```bash
npm i @uncle7/starmap-2d
```

```ts
import { createJourney } from '@uncle7/starmap-2d'

const journey = createJourney(document.querySelector('#stage'), manifest, {
  onEnterCruise: (i) => console.log('进入第', i, '段光隧'),
})
```

宿主需要给容器一个**明确的高度**（`position:fixed; inset:0`，或 `width/height:100%`）。
库只填满宿主给的盒子；盒子高度为 0 时它会警告，而不是静默画错。

**零运行时依赖** —— 没有 three.js，没有 canvas 库。一级是 SVG，二级是 Canvas 2D。

## 与三维版并存

| | `@uncle7/starmap` | `@uncle7/starmap-2d`（本包） |
|---|---|---|
| 一级星图 | three.js 正交相机 | **SVG** |
| 站点符号 | 四种三维几何体 | **制图符号** |
| 二级巡航 | three.js 场景 | **Canvas 2D 光隧** |
| 运行时依赖 | three | **无** |

两个包共用同一套内容标准（`Manifest`）、同一套航线布局、同一套档位状态机 ——
**同一份内容在两边画出同一张图、同一条航线、同样的档位反应。**
换渲染器不换内容。

## 为什么一级是 SVG

三维版用 three 的正交相机画一张**平面图**。那是全库最浪费的一处：
正交相机的平面图和 SVG 的差别，只剩下「文字能不能点」这一项 ——
而这一项 DOM 赢、SVG 的 `<text>` 也赢不了。

SVG 还顺带解决了两件事：

- **放大不糊。** 截图放大到任何倍率都是矢量。
- **线是发丝线。** SVG 的线宽默认跟着坐标系缩放 —— 一个世界单位是十几像素，
  网格和航线就全成了粗色块。所以全图开 `vector-effect: non-scaling-stroke`，
  线宽钉死在 1 设备像素。

## 为什么符号改成制图符号

三维版那四个「线条构成的三维几何体」（测地体 / 陀螺仪 / 纽结 / 晶格）
在平面图上其实不好认 —— 它们靠**转动**才看得出是三维的，而图是静的。

海图符号的读法是**先看形状，再看颜色**：颜色只能区分三四个，形状才能区分十几个。
所以四种符号的轮廓必须一眼能分开：

| 符号 | 轮廓特征 | 海图上的含义 |
|---|---|---|
| `anchor` 锚 | 竖长 | 锚地 / 泊位 |
| `star` 星标 | 尖刺朝外 | 显著物标 |
| `diamond` 菱形十字 | 硬角 | 位置（国际海图符号） |
| `beacon` 灯标 | 圆 + 光芒 | 灯标及其光质 |

**不变式**：`相邻站间距 ≥ 符号外框直径`，由 `debug().map.minGap` 守着 —— 量出来，不是推算。

## 一级 · 星图：一张宇宙航行的海图

```
站点 → 航路点符号     旅程 → 航线（按次序直连，带航向箭头）
时间 → 网格          空间感 → 星尘在图廓之外闪
```

| 海图上的东西 | 实现 |
|---|---|
| 航路点符号 | 四种制图符号，按色相区分 |
| 航线 | 按时间次序**逐段直连**，每段带航向箭头 |
| 标注 | 站号 · 年月 · **地点**（海图上标注的是地点，不是活动名） |
| 经纬网 | 细格 + 每 N 格一道粗格 |
| 斜航线 rhumb | 从中心辐射的 32 向等角线 |
| 罗盘玫瑰 | 外环 + 32 向刻度 + 四向主辐线，**自动落到离站点最远的那个角** |
| 图廓 | 边框 + 四角标记，**四边正好压在画幅边上** |

**标注只放「时间 + 地点」**：13 个站排成一条航线，标注宽度必须小于站距才排得下。
完整站名 / 角色 / 受众放在悬停提示与读屏标签里 —— 图上是索引，提示里是全文。

**没有指针视差。** 海图不能有视差：读者要靠比例判断距离，一动比例就作废了。
所以**图是静的，只有图廓之外的星在闪**。这同时让截图更可靠 —— 动的东西永远截不准。

**图幅跟着视口走。** 图廓不是一张方纸，它就是**这块画布的边界**。
所以视口一变，图幅就重画一次；罗盘也自动挪到离站点最远的那个角 ——
固定一个角会被航线和标注压住。

## 二级 · 光隧：一条只由深度决定的隧道

```
    你在看哪儿，隧道就朝哪儿开
    划得越快，环冲得越快、内容从眼前掠过
    划得慢，它就停在半路等你看
```

### 一切只由深度决定

屏幕上每个东西的位置都来自一条式子：**r = K / z**（z 是深度，r 是屏幕半径）。

这条 1/z 律就是「隧道」的全部来源 —— 远处的环挤在消失点成一小簇，
近处的环撑满画幅，一眼就看出这是穿过的东西，而不是雷达屏上等距的同心圆。

内容也挂在同一根线上：它在 z = Z_FAR 诞生，一路朝你冲过来，
半径自己胀大，到达转向点时按你的速度决定是**掠过飞走**还是**掉头退远**。

### 项目环：一站一个环，站名时间地点绕着环排

每一站外面套一个环 —— **上弧走站名，下弧走时间地点**，两边字都正着念。

```
              ┌─────────────┐
              │ AIGC 创新实践周 │      ← 上弧：站名
        ╭─────┴─────────────┴─────╮
       │   双圈 + 72 格刻度的表圈     │
       │      （隧道结构环）           │
        ╰─────────────────────────╯
              │ 01 · 2024-04-08 · 南京艺术学院 │   ← 下弧：序号 时间 地点
```

环从远处来 → **停住让人读** → 冲过去。停住那一段是这一站的「读图时间」。

三件让弧形文字站得住的事：

1. **上弧和下弧的转角不同**（`ca + π/2` / `ca - π/2`）。用错一条下弧的字会倒过来。
2. **字描一圈深色边。** 环上的字会压到浅色照片上（海报、课堂照），
   浅蓝字在浅色海报上几乎读不出来。描边是**字缘**，不是底板。
3. **轴心有纵向硬边界。** 环停住时的半径是确定的（按画幅短边算），
   上弧该落在哪儿也就确定了 —— 轴心在这个范围里走，站名就永远在画幅内。
   指针往上一甩，站名不会跟着飘出顶边。

### 三条规矩

1. **档位由指针速度决定**：慢 = 只放行 highlight，快 = overview / details 也放行。
2. **图的死活由读者决定**：读者移速决定流速，流速决定它冲多快、什么时候走。
3. **点一下 = 钉住那一张**：它停在那个深度上，并拿到眼前来看。

### 确定性

没有 `Math.random()`：素材顺序用站号做种子的定序洗牌，星尘用固定种子的 mulberry32。
同一站永远以同样的顺序出场 —— 这个库的用途之一是**被截图**，每次刷新都换一套的库没法当效果资产用。

`journey.freeze()` / `journey.thaw()` 可以把画面钉住再截：截图往返有几百毫秒，
稍纵即逝的帧（「掠过」只有零点几秒）抓不住，只能先停住。

## 内容契约

库只认 `Manifest`：

```ts
interface Manifest {
  title?: string
  stations: Station[]
}

interface Station {
  id: string              // kebab-case，唯一
  title: string
  date?: string           // YYYY-MM / YYYY-MM-DD，排序唯一依据
  end?: string
  place?: string
  short?: string          // 图上标注用的短地名，缺省用 place
  role?: string
  audience?: string
  lead?: string
  summary?: string
  draft?: boolean         // 未校订的占位文案
  images: ImageRef[]      // { src, tier: 0|1|2, caption? }
}
```

**能校验的绝不默认值。** 字段缺失有明确的降级路径，字段写错必须报错，
而不是悄悄按缺省渲染出一个错的页面 —— `validateManifest()` 会抛 `ManifestError`（带路径）。

`images[].tier` 就是 LOD：`0` 高亮 / `1` 概览 / `2` 细节。
目录分类同时就是 LOD 数据。

把标准目录读成 manifest 用附带的工具：

```ts
import { readStations } from '@uncle7/starmap-2d/content'

const manifest = await readStations('./stations', { base: '/stations' })
```

## API

```ts
const journey = createJourney(container, manifestInput, options)
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `speedBase` | 260 | 指针速度基准（px/s）。档位判定用**相对倍率**，换设备只改这一个数 |
| `imageExit` | `'auto'` | 图退场方式：`auto` / `sweep`（掠过飞走）/ `recede`（掉头退远） |
| `forceTier` | `null` | 强制档位（0/1/2），给自动化与截图用 |
| `shape` | `'star'` | 站点符号 |
| `layout` | — | 航线排布参数（见下） |
| `course` | — | 航线样式；`false` = 不画航线 |
| `chart` | — | 网格步长、罗盘开关 |
| `hint` | — | 光隧的开场提示语。不给就不显示 —— 库里不替宿主说话 |
| `debug` | `false` | 画面上显示读数 |

| 方法 | 说明 |
|---|---|
| `journey.goto(i)` | 跳到第 i 站的光隧 |
| `journey.toMap()` | 回到星图 |
| `journey.freeze()` / `thaw()` | 定格 / 恢复（截图用） |
| `journey.on('view' \| 'hover', cb)` | 订阅视图与悬停 |
| `journey.debug()` | 取景与投影的真实数值。**排布是纯函数，出问题要看数，不要靠感觉** |
| `journey.destroy()` | 拆掉 |

### 排布

航线是**算出来的，不是排出来的**（固定种子的分形噪声 + 沿弧长等距布点 + 逐站避让），
和三维版同一套参数：

| 选项 | 默认 | 说明 |
|---|---|---|
| `spacing` | 6.4 | X 站间距。必须小于符号外框直径 |
| `riseRatio` | 0.45 | 整体升幅 / 水平跨度 |
| `meander` | 0.30 | 蜿蜒幅度 / 水平跨度。0 = 直线 |
| `meanderFreq` | 1.0 | 空间频率 |
| `seed` | `'star-chart'` | 换它就换一条航线 |
| `radius` | 2.2 | 符号半径 |

## 开发

```bash
pnpm install
pnpm gen:manifest   # 把 ../stations 读成 examples/demo/public/manifest.json
pnpm dev            # 起 demo
pnpm typecheck
pnpm check:tier     # 档位状态机的 11 条断言
pnpm build
```

`examples/demo/public/stations` 是指向 `../stations` 的目录联接（Windows 本机用）。
正式接入时素材前缀由宿主的静态资源根决定，库本身不关心。

### 目录

```
src/
  types.ts        内容契约与校验
  layout.ts       程序化航线布局（与三维版同一份）
  window.ts       速度平滑 + 档位状态机（与三维版同一份）
  content/reader.ts  把标准目录读成 manifest（Node 侧）
  chart.ts        SVG 海图底：网格 / 斜航线 / 罗盘 / 图廓
  symbol.ts       制图符号
  course.ts       SVG 航线
  labels.ts       HTML 标注覆盖层
  map.ts          一级星图组装
  cruise.ts       二级光隧
  index.ts        公共 API + CSS
```
